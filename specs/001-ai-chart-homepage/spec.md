# Feature Specification: AI Chart Generator Homepage

**Feature Branch**: `001-ai-chart-homepage`  
**Created**: 2026-02-24  
**Status**: Draft  
**Input**: User description: "AI驱动的图表生成首页，用户输入数据提示词，自动提取数据并智能选择图表类型渲染"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基础图表生成 (Priority: P1)

用户访问 AI Charts 官网首页，看到一个居中的输入框。用户输入包含数据的自然语言描述（例如："帮我比较一下今年一到六月，北京和上海的月度销售额：北京是 120、130、150、170、180、200；上海是 100、140、160、150、190、210"），点击发送按钮。系统调用 AI 处理输入，提取数据内容，自动选择合适的图表类型（折线图、柱状图等），并在页面上展示生成的图表。

**Why this priority**: 这是核心功能，没有基础的图表生成能力，整个产品就没有价值。用户能够输入数据并看到可视化结果是最基本的 MVP。

**Independent Test**: 可以通过访问首页，输入包含数值数据的文本，验证是否能看到展示数据的图表。即使没有其他功能，这个流程本身也能演示产品的核心价值。

**Acceptance Scenarios**:

1. **Given** 用户在首页看到居中的输入框，**When** 用户输入"2024年销售额：1月100万，2月120万，3月150万"并点击发送，**Then** 系统展示一个柱状图或折线图，X轴显示月份，Y轴显示销售额数值
2. **Given** 用户输入包含多组数据的文本（如北京和上海的对比数据），**When** 点击发送，**Then** 系统展示包含两条数据系列的图表，清晰区分不同数据组
3. **Given** 用户输入的数据格式不规范或缺少关键信息，**When** 点击发送，**Then** 系统显示友好的错误提示，引导用户如何正确输入

---

### User Story 2 - 响应式布局转换 (Priority: P2)

当用户在首页输入数据并生成图表后，页面布局自动调整：输入框从居中位置移动到页面底部（类似聊天界面），图表显示区域出现在页面上方。用户可以继续在底部输入框中输入新的数据或修改请求，查看新的图表结果。

**Why this priority**: 这提升了用户体验，使得界面更加直观和现代化。布局转换让用户可以同时看到历史图表结果和输入新请求，提高了工作效率。虽然重要，但不是 MVP 的必需功能。

**Independent Test**: 可以通过生成第一个图表，观察布局是否从"居中输入框"变为"顶部图表+底部输入框"，验证交互体验的流畅性。

**Acceptance Scenarios**:

1. **Given** 用户首次访问首页，**When** 页面加载完成，**Then** 输入框显示在页面中央，无图表显示区域
2. **Given** 用户已输入数据并生成了第一个图表，**When** 图表渲染完成，**Then** 输入框平滑移动到页面底部，图表显示在上方区域，占据主要空间
3. **Given** 用户在底部输入框中输入新的数据请求，**When** 点击发送，**Then** 新图表替换旧图表（或在上方添加新图表），输入框保持在底部位置
4. **Given** 用户在移动设备上访问，**When** 生成图表后，**Then** 布局转换仍然流畅，图表适配移动端屏幕尺寸

---

### User Story 3 - 用户指定图表类型 (Priority: P3)

用户可以在输入的自然语言中明确指定想要的图表类型（例如："用饼图展示各部门预算占比"或"用折线图显示销售趋势"）。系统识别用户指定的图表类型（柱状图、折线图、饼图、散点图等），并优先使用指定的类型进行渲染，而不是自动推荐。

**Why this priority**: 这给予用户更多控制权，满足高级用户的定制需求。但对于大多数用户，自动选择图表类型已经足够，所以优先级较低。

**Independent Test**: 可以通过输入明确包含图表类型的请求（如"用饼图显示..."），验证系统是否按照用户指定的类型渲染，而不是自动选择其他类型。

**Acceptance Scenarios**:

1. **Given** 用户输入"用柱状图显示2024年各月销售额：1月100，2月120，3月150"，**When** 点击发送，**Then** 系统生成柱状图（而非折线图或其他类型）
2. **Given** 用户输入"用饼图展示市场份额：产品A 40%，产品B 35%，产品C 25%"，**When** 点击发送，**Then** 系统生成饼图展示份额分布
3. **Given** 用户输入数据但未指定图表类型，**When** 点击发送，**Then** 系统智能选择最合适的图表类型（如时间序列数据使用折线图，占比数据使用饼图）
4. **Given** 用户指定了不适合该数据类型的图表（如用饼图展示时间序列），**Then** 系统提示建议的图表类型，但仍尊重用户选择进行渲染

---

### User Story 4 - 图表交互和优化 (Priority: P4)

生成的图表支持基本交互功能，如鼠标悬停显示数据详情、缩放、图例切换等。图表具有良好的视觉效果，包括合理的配色、清晰的标签、响应式尺寸调整。

**Why this priority**: 这些是锦上添花的功能，提升专业性和用户满意度，但不影响核心价值交付。

**Independent Test**: 生成图表后，测试鼠标悬停、点击图例等交互，验证功能是否正常工作。

**Acceptance Scenarios**:

1. **Given** 用户已生成一个图表，**When** 鼠标悬停在数据点上，**Then** 显示该数据点的具体数值和标签
2. **Given** 图表包含多个数据系列，**When** 用户点击图例中的某个系列，**Then** 该系列在图表中隐藏/显示（切换可见性）
3. **Given** 用户在桌面浏览器上查看图表，**When** 窗口大小改变，**Then** 图表自动调整尺寸保持良好展示效果
4. **Given** 图表展示完成，**When** 用户查看图表，**Then** 配色方案清晰易读，文字标签不重叠，整体美观专业

---

### Edge Cases

- **空输入或无效输入**：用户未输入任何内容或输入纯文本（不含数据）时，系统如何响应？应提示"请输入包含数据的描述"。
- **数据格式多样性**：用户可能用不同方式描述数据（"100万"、"1M"、"1,000,000"等），系统需要识别并规范化。
- **数据量过大**：如果用户输入包含数百个数据点的文本，图表渲染性能如何保证？可能需要数据采样或提示用户简化。
- **AI 解析失败**：如果 AI 无法准确提取数据或理解意图，系统应提供友好的错误信息和示例引导。
- **网络错误**：调用 AI API 失败或超时时，系统应显示重试选项和错误说明。
- **多语言支持**：如果用户用英文或其他语言输入数据，系统能否正确解析？（初期可只支持中文）
- **图表类型不支持**：用户指定的图表类型当前系统不支持（如雷达图、热力图），应如何处理？提示支持的类型列表。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在首页展示一个输入框组件，初始状态时该输入框居中显示
- **FR-002**: 系统必须支持用户输入自然语言文本，文本内容可包含数据、描述和图表类型需求
- **FR-003**: 系统必须提供"发送"或"生成"按钮，用户点击后触发图表生成流程
- **FR-004**: 系统必须调用 AI 服务（通过 Next.js API Route）来解析用户输入的自然语言
- **FR-005**: AI 服务必须能够从用户输入中提取结构化数据，包括：
  - 数值数据（如销售额、数量、百分比等）
  - 标签/类别（如月份、城市名、产品名等）
  - 数据系列名称（如"北京"、"上海"）
- **FR-006**: AI 服务必须能够识别用户输入中的图表类型指定（如"柱状图"、"折线图"、"饼图"等关键词）
- **FR-007**: 系统必须实现智能图表类型选择逻辑：
  - 如果用户明确指定图表类型，使用指定类型
  - 如果用户未指定，根据数据特征自动选择（时间序列→折线图，占比→饼图，对比→柱状图等）
- **FR-008**: 系统必须使用 ECharts 库渲染图表，支持的基础图表类型至少包括：
  - 折线图（Line Chart）
  - 柱状图（Bar Chart）
  - 饼图（Pie Chart）
- **FR-009**: 生成图表后，系统必须执行布局转换：
  - 输入框从中央移动到页面底部
  - 图表显示区域出现在页面上方
  - 转换动画应流畅自然
- **FR-010**: 系统必须在图表上方或底部输入框中保持用户输入的历史记录或当前输入
- **FR-011**: 用户在生成第一个图表后，必须能够继续在底部输入框中输入新的数据请求
- **FR-012**: 系统必须处理输入验证：
  - 空输入时禁用发送按钮或提示用户
  - 无法识别数据时返回友好错误提示
- **FR-013**: 系统必须在 AI 处理过程中显示加载状态（如加载动画或进度提示）
- **FR-014**: 生成的图表必须具备基本配置：
  - 清晰的 X 轴和 Y 轴标签（如适用）
  - 图例（当有多个数据系列时）
  - 合理的配色方案
  - 响应式尺寸（适配不同屏幕）
- **FR-015**: 系统必须在 API 调用失败或超时时显示错误信息，并提供重试选项
- **FR-016**: 所有前端组件必须使用 Tailwind CSS 和 shadcn/ui 构建（符合项目宪法）
- **FR-017**: 所有后端接口必须使用 Next.js API Route 实现（符合项目宪法）

### Key Entities

- **用户输入（UserInput）**：
  - 原始文本内容
  - 提交时间戳
  - 解析状态（成功/失败）
  
- **结构化数据（StructuredData）**：
  - 数据系列数组（每个系列包含名称和数值数组）
  - 类别/标签数组（X 轴标签）
  - 数据类型标识（时间序列、分类、占比等）
  
- **图表配置（ChartConfig）**：
  - 图表类型（line、bar、pie 等）
  - 标题
  - 数据系列
  - 样式选项（颜色、主题等）
  - ECharts option 对象
  
- **AI 响应（AIResponse）**：
  - 提取的结构化数据
  - 推荐的图表类型
  - 置信度或成功标识
  - 错误信息（如解析失败）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在 3 秒内找到并使用首页的输入框（通过用户测试验证）
- **SC-002**: 用户输入包含数据的提示词后，90% 的情况下系统能够成功提取数据并生成图表
- **SC-003**: 从用户点击"发送"到图表完整渲染完成，整个过程在 5 秒内完成（在正常网络条件下）
- **SC-004**: 图表渲染后的布局转换动画流畅，用户体验评分达到 4/5 或更高
- **SC-005**: 生成的图表在桌面端（1920×1080）和移动端（375×667）上均能正确显示，无布局错乱
- **SC-006**: 当用户明确指定图表类型时，系统使用指定类型的准确率达到 95% 以上
- **SC-007**: 系统能够识别并正确处理至少 5 种常见数据格式表达方式（如"100万"、"1M"、"1,000,000"）
- **SC-008**: 用户首次使用时，80% 的用户能够在不查看文档的情况下成功生成第一个图表
- **SC-009**: 系统在 API 调用失败时，100% 的情况下显示友好错误提示（而非技术错误信息）
- **SC-010**: 页面支持 1000 个数据点以内的图表渲染，渲染时间不超过 2 秒
- **SC-011**: 新用户完成从输入数据到查看图表的完整流程，平均耗时少于 30 秒
- **SC-012**: 生成的图表符合可访问性基本标准，颜色对比度达到 WCAG AA 级别
